## 1. 一句话定位

粘贴简历 + 公司 JD（各一个输入框），选一种面试类型，AI 面试官跟你完整走一轮 8–10 个问题的模拟面试；**每答完一题，旁边立刻出现多维打分**（由 JEV 模型评估，与大模型面试官解耦）；打字、说话都行。面完出一份总报告。

**这不是产品卖给别人的 PRD，是一期自己用的训练工具——先把自己练强，再考虑产品化。**

---

## 2. 背景与问题

- 真实面试机会贵、反馈缺失：面完只知道"过没过"，不知道**哪一题、哪个维度**丢了分。
- 通用 LLM 聊天练面试的两个痛点：
  1. **球员兼裁判**：提问和评价是同一个模型，评价随口、不可复现、没有分维度量化；
  2. **没有终止条件**：聊到哪算哪，练不出"40 分钟内答好 8 题"的节奏感。
- 解法：把「提问/追问」和「评分」拆成两个独立模块——
  - **面试官 Agent（LLM）**：只负责像真人一样提问、追问、控场；
  - **JEV 测评模块**：只负责按固定量规给每个回答打多维分（快、便宜、可复现、带置信度）。

## 3. 一期范围（Scope）

### 3.1 做（In Scope）

| # | 功能 | 说明 |
|---|---|---|
| F1 | 简历 + JD 输入 | **各一个文本输入框，粘贴全文即可**；txt / md 文件可直接拖入框内自动填入；两者都可留空（空则面试官不引用材料，直接开问） |
| F2 | 面试类型选择 | **技术面 / HR 面 / 高管面** 三种人格，各有独立提问策略与题量配比 |
| F3 | 对话式面试 | 单轮主问题 8 个（可配 8–10），每个主问题最多 1 次追问；不严格计时，但以题量控制"约 40 分钟"的体量 |
| F4 | JEV 每题多维打分 | 每次收到回答（主答或追问答）后 1–2 秒内，在消息旁展示维度分卡片 |
| F5 | 双通道输入 | 打字输入 + 语音输入（浏览器录音 → 本地 Whisper 转文字） |
| F6 | 面试报告 | 全部答完后生成：逐题得分表 + 维度雷达 + 三条最优先改进建议 |
| F7 | 会话保存 | 本地持久化，可回看历史面试与打分 |

### 3.2 不做（Out of Scope，二期再议）

- **PDF / docx 简历解析、文件拖拽上传区**（一期只用纯文本粘贴，避免为解析库付出复杂度；二期再加上传解析）
- 视频面试 / 摄像头 / 表情神态分析（JEV 只吃文本，一期不做多模态）
- AI 语音播报面试官（TTS）——一期面试官只出文字
- 多轮简历优化建议、AI 改简历
- 面试题库 / 八股文背诵模式
- 多用户 / 账号体系 / 云端部署

## 4. 用户流程（主路径）

```
① 新建面试
   简历框：粘贴简历全文（一个框）
   JD 框：粘贴目标岗位 JD 全文（一个框）
   选择面试类型：技术面 | HR面 | 高管面
   选择题量：8 / 9 / 10
        │
        ▼
② 开场（Agent）
   面试官自我介绍 + 第 1 题（题号 1/8 显示）
        │
        ▼
③ 回答循环（× 8~10）
   用户打字或按住说话 → 语音转文字 → 确认/直接发送
        │
        ├─→ 面试官 Agent：读完回答 → 追问（最多1次）或下一题
        └─→ JEV 模块：独立评估本次回答 → 消息旁浮出打分卡
        │
        ▼
④ 收尾（达到题量上限，或用户主动结束）
   面试官简短收尾语
        │
        ▼
⑤ 报告页
   逐题分数表 + 维度雷达 + 总评 + 3 条改进建议
```

**退出与恢复**：中途关闭可恢复（进度保存），对标参考原型的"进度会保存，回来接着聊"。

## 5. 核心机制设计

### 5.1 题量与节奏控制（"40 分钟"的正确打开方式）

- 不做硬性倒计时。控制体量的单位是**主问题数**：默认 8，允许用户在创建时选 8 / 9 / 10。
- 每个主问题最多 1 次追问，追问不占主问题额度（保证真实面试的"顺藤摸瓜"感）。
- 面试官 prompt 中注入节奏信息：`已用时长 X 分钟 / 已问 Y 题 / 剩余 Z 题`——若回答偏短，优先追问而非快速放题；接近尾声时收敛到收尾问题（如"你有什么想问我的"）。

### 5.2 双模块解耦（本项目的架构灵魂）

```
              ┌──────────────────────────┐
用户回答 ──┬─→│ 面试官 Agent（LLM）       │──→ 下一个追问 / 下一题 / 收尾
           │  │ MiniMax-M3 等聊天模型     │
           │  └──────────────────────────┘
           │  ┌──────────────────────────┐
           └─→│ JEV 测评模块              │──→ 多维打分卡（挂在消息旁）
              │ TypeSafe Decisions API    │     （低置信 → 标灰+提示重评）
              │ 一次请求并行 5~6 个原子问题 │
              └──────────────────────────┘
```

- 两者**互不感知、互不等待**：JEV 打分失败/重试不阻塞面试官出下一题。
- 打分卡异步出现，出现前显示占位骨架。

### 5.3 JEV 打分维度（一期定版量规）

利用 JEV「一次请求并行多问」+「Composite Scoring：复杂判断拆成原子问题，代码加权合成」的模式，每次回答发**一次** Decisions 请求，包含：

| 维度 | JEV 原语 | 量规（0–4 或 0–1） | 判断的问题示例 |
|---|---|---|---|
| **切题度** | score | 0-4：4=正面回答了所问；0=答非所问 | "该回答是否直接回应了面试官的问题？" |
| **完整性** | score | 0-4：要点覆盖程度（结合题目预期要点） | "该回答覆盖了问题期望的关键要点的程度？" |
| **条理性** | score | 0-4：结构清晰、有逻辑框架（如 STAR/总分总） | "该回答是否结构清晰、逻辑连贯？" |
| **简洁度** | noul | 是否存在明显重复、绕圈、车轱辘话（value 即信念度） | "该回答是否包含重复或冗余内容？" |
| **具体性** | score | 0-4：有无具体事例、数字、细节支撑 | "该回答是否包含具体事例或数据支撑？" |
| **总评档位** | choice | 优秀 / 良好 / 合格 / 待改进 | "综合该回答的面试表现属于哪一档？" |

- **置信度门控（v1.1 实测校准）**：JEV 的 confidence 实测集中在 0.5–0.8（维度）与 0.41–0.55（档位），**不是 0~1 均匀分布**，所以门控分两档：
  - 维度置信 < 0.45 → 整张打分卡打灰 + "仅供参考"，**不进均分**；
  - 档位置信 < 0.30 → 只把总评徽章半透明并加 `?`，不影响分数。
- 成本实测（v1.1）：单次 6 问决策 **$0.0000366**；一场 10 题 ×2（主答+追问）≈ 20 次 ≈ **$0.0007/场**，忽略不计。
- 延迟实测（v1.1）：JEV 与面试官 LLM 并行，端到端 **1.8s** 同时拿到打分与下一题。
- ⚠️ 已知坑（来自 JEV 项目实测）：概率和不等于 1 的偶发校验失败 → **作为可重试错误处理**，不中断面试。

### 5.4 三种面试人格

| | 技术面 | HR 面 | 高管面 |
|---|---|---|---|
| 视角 | 做事能力：项目深挖、技术选型、难点与权衡 | 匹配度：动机、稳定性、协作、自我认知 | 判断力：行业理解、战略思考、成长性、文化 |
| 题量配比（8题） | 项目深挖 4 + 硬技能 2 + 协作 1 + 反问 1 | 动机 2 + 行为 4 + 稳定性 1 + 反问 1 | 行业/业务 3 + 领导力 2 + 视野 2 + 反问 1 |
| 追问风格 | 顺技术细节追问（为什么这么选/数据量/失败过吗） | 顺行为细节追问（当时你具体做了什么/结果如何） | 顺判断追问（如果重来/你怎么看对手/代价是什么） |
| 简历+JD 的用法 | 从简历项目里挑深挖点，从 JD 提技能关键词 | 从 JD 提文化/软性要求，从简历找经历佐证 | 从 JD 提业务方向，从简历提炼决策片段 |

面试官人格只影响**提问与追问**，打分量规三类型通用（一期不拆分）。

### 5.5 语音输入

- 浏览器 MediaRecorder 录音（按住说话或点击开始/停止）→ 上传 webm → 后端本地 Whisper（mlx-whisper，已有管线）转文字 → 回填输入框（**用户可先确认再发送**，防转错）。
- 环境坑已在用户既有 Whisper 管线中解决（Python 用 `~/.workbuddy/binaries/python/envs/default`）。

## 6. 界面设计（对标截图原型）

### 6.0 新建页（Setup）——每类材料只有一个框

```
新建一场模拟面试
粘贴简历与目标 JD，选一种面试类型……

┌ 简历 ────────────────────────────────────────┐
│ 粘贴简历全文…（也可以不填，用示例简历）          │
│                                              │  ← 单个 textarea，
│                                              │    txt/md 可拖入，
│                                              │    高度可拉
└──────────────────────────────────────────────┘
用示例简历填充

┌ 目标 JD ─────────────────────────────────────┐
│ 粘贴目标岗位 JD…（也可以不填，用示例 JD）       │
└──────────────────────────────────────────────┘
用示例 JD 填充

面试类型   [技术面] [HR 面] [高管面]
主问题数量 [8 题] [9 题] [10 题]
        [开始面试]
```

设计要点：
- **一类材料一框**，不做「上传区 + 粘贴区」双入口（双入口会让用户犹豫该用哪个，且一期不支持 PDF 解析）。
- 两个框都是**可选**的，框下方各有一个「用示例填充」的次要按钮，方便零成本试跑。
- 拖入 `.txt / .md` 直接读文本填入；拖入 PDF/docx 时框内给出一行提示，请用户打开复制文本（不静默失败）。

### 6.1 布局

```
┌─────────────────────────────────────────────────┐
│  Interview Coach          [类型徽标:技术面]  ⏱ 23:18 │
├──────────────────────────────┬──────────────────┤
│                              │  本场概览         │
│   对话主区（单列气泡流）        │  进度 ●●●●○○○○ 4/8 │
│                              │  均分 3.2 / 4     │
│   [面试官] 第 3 题：…          │  ─────────────── │
│                              │  最近打分卡        │
│   [我] ……回答气泡              │  切题 4 完整 3     │
│     ┌ 打分卡（浮于气泡右上侧）  │  条理 3 简洁 ✓     │
│     │ 切题4·完整3·条理3·简洁✓  │  具体 2  总评:良好  │
│     │ 具体2 · 总评 良好        │  ─────────────── │
│     └ ─                      │  维度雷达（累计）   │
│                              │                   │
├──────────────────────────────┴──────────────────┤
│ [🎤 按住说话]  输入框…………                  [发送]  │
└─────────────────────────────────────────────────┘
```

要点：
- **打分卡**是本产品的记忆点：出现在每条用户回答气泡的旁侧，异步载入（骨架屏 → 数字弹出），≤ 2 秒。
- 顶部进度条显示 `已答/总题数` 与已用时长，弱化计时（只展示，不倒计时）。
- 结束按钮常驻（"提前结束并生成报告"）。
- 面完跳报告页：分数表 + 雷达图 + 逐题原文回看（回答与追问的完整对话）。

### 6.2 状态与异常提示

| 场景 | 提示方式 |
|---|---|
| 语音转写中 | 输入框内嵌"转写中…" |
| 转写完成 | 文字回填输入框，用户确认后发送 |
| JEV 低置信 | 打分卡变灰 + "置信度低，仅供参考" |
| JEV 连续 3 次失败 | 打分卡显示"本轮未评分"，面试不受影响 |
| 网络中断 | 对话可继续，恢复后补评未评的回答 |

## 9. 开放问题（做之前需要拍板）

1. **主问题数默认 8 还是 10？**（建议默认 8，10 留给"今天状态好"）
2. **追问的答也打分吗？**（建议打分但不计入雷达均分，只入逐题记录——避免鼓励答短等追问）
3. **LLM 用谁？** MiniMax-M3 已实测最稳最快（<1s、JSON 干净），建议一期就用它，配置化留切换口。
4. 报告的"改进建议"由谁生成？建议：分数统计由代码算，文字建议由面试官 LLM 基于全场回答+分数写——各干各的。
